    In a nutshell

    We built a multimodal retrieval-augmented generation (RAG) co-pilot for a Fortune 500 industrial automation company's engineering software. It answers automation engineers' technical questions from a verified knowledge base of more than 10,000 specifications, compliance guidelines, manuals, CAD schematics and SOPs, using Google Cloud for retrieval and Microsoft AI Foundry to govern every answer.

    What was going wrong
    • A knowledge bottleneck: when senior engineers were busy, away or left, their knowledge became hard to reach and work slowed.
    • Repeat questions: up to 40% of senior engineers' time went on repetitive questions and logic checks.
    • A steep learning curve: junior engineers needed close oversight to avoid configuration errors.
    • Slow change: modifying a control topology or adding a production line meant weeks of manual code checks, with configuration logic reviewed by hand for errors.

    03 · The resolution

    Google Cloud retrieves. Microsoft AI Foundry governs.

    Two paths. The build path turns documents into a searchable index once. The answer path runs every question through governance. Pick a path to trace it.

    Google Cloud · knowledge base, built once and kept in sync
    secure API gateway · query and context
    Every question · the answer path
    How the two paths work
    • The build path: Cloud Storage to Vertex AI RAG Engine to RagManaged DB through native connectors, built once and kept in sync.
    • The answer path: the engineering software to AI Foundry to a foundation model, with retrieval over a secure API gateway.
    • Foundry at the centre: every request runs under the engineer's Entra ID identity and passes guardrails on the way in and out.
    • Open on models: Gemini or GPT can write the answer; the governance around it stays the same.
    04 · Building the knowledge base

    From 10,000 files to a searchable index

    Steps 1 to 4 happen once and stay in sync. Step through them to see a schematic become something the co-pilot can reason over.

    What each step does
    • One verified source: manuals, CAD schematics, SOPs, specifications and compliance guidelines in Cloud Storage, synced from Google Drive.
    • Pictures carry answers: the Gemini multimodal parser turns charts, circuit topologies and drawings into descriptive text and vectors.
    • Configured, not coded: Vertex AI Studio handles chunking and embeddings; Cloud Spanner scales with built-in sharding and strict isolation.
    • Behaviour outside the code: prompts, guardrails and output rules are versioned in the console and change without redeploying.
    Where expertise comes fromDocuments. The co-pilot answers only from the knowledge base, which holds historical technical documentation alongside manuals, schematics and SOPs. What one expert knows reaches every engineer once it is written down and added.
    05 · The answer path

    From question to governed answer in seconds

    Steps 5 to 7 run every time an engineer asks. Pick a request and replay it through every service it touches.

    Request trace0 ms
      Sample request · timings are illustrative
      What happens on every question
      • Step 5, the engineer asks: inside the engineering software; Foundry checks identity through Entra ID and applies safety controls first.
      • Step 6, retrieval: Foundry calls the Vertex AI RAG Engine through a secure API gateway; Spanner returns the best passages and diagram descriptions.
      • Step 7, the governed answer: a foundation model such as Gemini or GPT writes from that context; Foundry checks it before it is shown.
      • Beyond troubleshooting: for configuration tasks it pre-generates automation code blocks, checks each block for errors before the engineer sees it and suggests reusable libraries.
      06 · What makes it different

      Each platform does the job it does best

      Tap a job to see who owns it. Google Cloud does the data-heavy work, Microsoft AI Foundry runs the governed agent, and the client's engineering software is where engineers work.

      Google CloudVertex AI · Cloud Spanner

            Why two platforms
            • Set by the brief: the design had to span Google Cloud and Microsoft environments and meet enterprise-grade identity governance and security requirements.
            • Google Cloud for retrieval: native ingestion, Gemini parsing for diagrams and Cloud Spanner vector storage that scales to large engineering datasets, on managed services rather than custom vector database infrastructure.
            • Microsoft AI Foundry for governance: identity through Entra ID, safety enforcement, agent lifecycle management and orchestration of the retrieval call, in one runtime.
            The splitGoogle Cloud's retrieval at scale, under Microsoft's enterprise governance, with nothing new for engineers to learn.
