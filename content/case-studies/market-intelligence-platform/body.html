    In a nutshell

    We designed, built and documented a market intelligence platform for a Fortune 1000 industrial manufacturer: a console where business users collect product and pricing data on the client's brand and competing brands such as Fleetguard, Mann-Filter, Hengst, Parker Racor and Baldwin. A Next.js console fronts a Flask API that orchestrates ParseHub and six custom scrapers, stores everything in Snowflake, and runs in production on Azure Kubernetes Service.

    Client data protectedPrices and most part numbers are masked.     01 · The problem

    Long catalogs, broken runs, untraceable data

    One early extraction captured 1,269 of 3,413 of the client's products before it stopped. Replay that run, then replay it with the platform.

    A 3,413-product catalog
    0 of 3,413 products
    What was going wrong
    • Engineers for routine work: starting a job, checking it had finished and gathering output all needed a technical operator.
    • Shifting formats: results varied by site and by run, so analysts reworked them before comparing a price or part number.
    • Demanding data: several brands, four regions, multiple currencies, European comma decimals and cross-reference part numbers in titles.
    • No way back in: an interrupted run left a partial dataset and no reliable way to continue where it stopped.

    Start from the operator. Work back to the architecture.

    The briefOne controlled system that non-engineers can operate, and whose output analysts can trust.
    03 · How it works

    Six stages from web page to export

    Follow one product record through the platform. Pick a stage to see exactly what the record looks like there.

    What happens to every record
    • Normalized once: product name, part number, brand, price, currency, country, source URL, page number and extraction time.
    • Part numbers untangled: the first primary part number is kept, and cross-reference numbers go in their own field.
    • One price format, source currency: European decimals such as 1.234,56 become 1234.56, and currency symbols map to ISO codes. Each price stays in the currency of its source, with the ISO code in its own field.
    • Never twice: ingestion is idempotent per run token, so replaying a run never duplicates rows.

          Why Run and Resume are separate
          • Run opens a new session: a fresh lifecycle, starting at page one, with its own run token.
          • Resume continues: only when a session is active, pages remain, the next page resolves and nothing else is running.
          • No overlaps: a short database lock and a conflict check stop two people, or a person and a schedule, starting the same project.
          • No silent loops: checkpoint logic blocks a project whose resume makes no forward progress, until someone reviews it.
          05 · Collection engines

          Where ParseHub stops, six custom scrapers take over

          ParseHub handles stable listing pages. Six Python scrapers cover dynamic sites, supplier portals and local-language catalogs, and all of them deliver the same record shape.

          How the custom scrapers stay resilient
          • Patterns over selectors: extraction reads product names, URL slugs and image alt text, so layout changes break less.
          • Sessions that persist: saved cookies let logged-in supplier-portal work continue across runs.
          • Built for the site: Selenium, Playwright or DrissionPage, chosen per target, with local locales where markets need them.
          • One path out: scraper output goes through the same ingestion, storage and export path as ParseHub runs.
          Where operation ends and engineering begins
          • Configured projects: business users find, run, resume, schedule and export them in the console, and import project metadata in bulk. The user guide covers each step.
          • New or changed ParseHub sources: a project built in ParseHub reaches the console through project sync. The client guide covers templates, fields, regex and adapting a project to a new brand.
          • Custom scrapers: these are Python code. Adding one, or repairing one after a site changes, is engineering work, documented in the scraping-suite guide.
          • The platform itself: changes to the API, database, automation or deployment follow the technical handover's change procedures and the deployment guide.

          From a finished run to a price comparison
          • Check coverage: each project shows pages collected against the total pages in its metadata, and a project whose resume stops advancing shows as Blocked until someone reviews it. Coverage is checked against the catalog, not assumed from a finished run.
          • Check the records: ingestion tests every record for a part number, a numeric price, a recognized currency and a valid source URL. A row that looks wrong traces back to its source URL, page number, run and session.
          • Export the right scope: the latest run or a whole cumulative session, as CSV for business review or JSON for system-to-system handoff.
          • Compare the market: the client's brand and competing brands arrive in one record shape, so analysts can set the client's prices and part numbers beside competitors' in the same market without reworking formats first.
          07 · Architecture and release

          Secrets stay on the server. Releases ship on every push.

          Every browser action follows one path, and every release follows one pipeline. Pick one to trace it.

          Built for production
          • A server-side gateway: Next.js routes inject the backend key, normalize errors and handle uploads and downloads; the browser never calls the API.
          • Separate keys: standard routes need a bearer key, internal automation a separate key, and the ParseHub webhook its own secret.
          • Containers on AKS: console and API in separate Docker images, behind NGINX ingress with managed TLS, inside the client's environment.
          • Safe by default: schema creation at startup is off unless enabled on purpose, so a routine deployment never alters the database.
