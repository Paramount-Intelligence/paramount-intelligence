    In a nutshell

    Flexagon, a PE-backed enterprise software company, builds FlexDeploy and ConfigSnapshot, platforms for DevOps automation, application deployment, configuration management and release orchestration. We built a support copilot that reads each Freshdesk ticket, retrieves the relevant knowledge from across the company, drafts a grounded response and routes it through review and approval, so support engineers spend less time searching and more time resolving.

    01 · The problem

    Every answer started with a search

    To answer one ticket, an engineer often checked six places by hand, then wrote the reply from scratch. The quality of the answer depended on who picked the ticket up.

    What was slowing support down
    • Research time: engineers spent significant time investigating each issue across systems.
    • Uneven answers: response quality varied with each engineer's experience.
    • Scattered knowledge: documentation, tickets and engineering records lived in separate tools.
    • Unused history: past resolutions were hard to find and reuse at scale.
    • Repetitive drafting: similar responses were written again and again.
    • No quality signal: there was no view of how reliable a response was before it went out.
    The needFaster, consistent answers, with support engineers still in control of what customers receive.

    03 · The resolution

    A copilot that lives inside Freshdesk

    Ten n8n workflows built around one core orchestration flow, with Claude for drafting, Qdrant for retrieval and Postgres for memory. Tap any part to see its job, or trace a ticket through the system.

    How it's put together
    • One core flow: a 58-node n8n workflow carries every ticket event from webhook to reply or review.
    • Modular APIs: drafting, attachments, context, editing and approval each run as their own workflow, so each can change safely.
    • Retrieval-augmented drafting: Claude writes from knowledge retrieved from Qdrant, indexed with OpenAI embeddings.
    • State you can audit: sessions, context versions, drafts, confidence and routing decisions are kept in Postgres.

    05 · Inside the draft

    Every draft is built from Flexagon's own knowledge

    The Draft and Edit API gives Claude the ticket, its history and the company's knowledge, and gets back a structured draft with a confidence score. Tap an input or a part of the draft.

    How it fits

    Six kinds of input go in. A draft in five parts comes out, with a confidence score that decides where it goes next.

    Attachment intelligence

    TXTLOGCSVPDFDOCXImagesZIP

    Supported attachments are downloaded, then read or analyzed so the draft can reason over screenshots, logs and documents. Results are cached by file fingerprint, so the same file is never processed twice, and count and size limits keep processing predictable.

    Confidence score

    0 to 100Every draftSaved in PostgresGate 4 of 5

    Claude scores its own confidence in each draft, from 0 to 100, and returns the score with the draft and the context it used. It is the copilot's signal of how reliable a draft is before anything goes out. The score is saved with the draft in Postgres, and at routing a score of 60 or below sends the draft to a support engineer.

    07 · Human in the loop

    The support engineer stays in charge

    The private note links to a Review Interface. There the engineer can edit by hand, ask the AI to revise, add context and approve. Try each action.

    What changes for a support engineer
    • Before: one ticket often meant checking six places by hand, then writing the reply from a blank page.
    • Routine messages: thank-yous, requests to close and reports that the issue is fixed are handled without an AI draft, and the action is logged.
    • Real follow-ups: by default, the ticket already carries a private note with a researched draft, the context it used and a review link.
    • The engineer's part: open the review link, check the evidence and references behind the draft, edit it or ask the AI to revise it, then approve it and send it to the customer.

    What the reviewer can do
    • Open from Freshdesk: the private note carries the draft and a link to the Review Interface.
    • Edit by hand: changes are saved to the ticket session and approval is enabled.
    • Ask the AI to revise: a new draft is generated from the engineer's instruction and context.
    • Add context: notes and files are stored and used in the next draft.
    • Approve: the final draft is converted to HTML, marked as approved and posted as a private note.
    • Everything recorded: drafts, edits and decisions stay in Postgres for audit and debugging.
    After approvalThe approved draft sits on the ticket as a private note, and the engineer sends it to the customer from Freshdesk. On the review path, nothing reaches a customer before an engineer approves it.
